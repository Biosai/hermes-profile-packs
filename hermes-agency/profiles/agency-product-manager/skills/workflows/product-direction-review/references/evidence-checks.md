# The evidence checks

What this review looks at before `roadmap-decision` weighs anything. Each check ends in a number or a quoted source, never an impression.

## 1. The cohort
Quote how many outside users reached the core use, with the window. With fewer than about ten, retention cannot be measured yet. Recruiting testers is then the lever for product learning, not only for acquisition.

## 2. Frequency against the core loop
How often does the user's problem recur, and does the product sit on that recurrence? Compare with the core loop of the leading alternatives, not with their feature lists. A problem that recurs many times a day is won by a loop of a few seconds; a product used in sessions serves an occasional need.

## 3. Where the first session ends
When the value lands outside the product, later, the product needs a loop back to that moment (a check-in on the outcome), on the channel that actually reaches users. Count each channel's reach per outside user before choosing it.

## 4. What already exists
Read the code before proposing a build: re-ordering an existing capability is far cheaper. Say "read in code, not verified end to end" until the capability is probed in production.

## 5. A proposed feature: four tests before any yes
1. **The rules of the platform where the output is used.** Read them, and label the source primary or third-party.
2. **The product's own stated principles.** A feature that contradicts them is a no, even if it would sell.
3. **Whether competitors already sell it.** A commodity is no edge.
4. **How often it would be used.** A one-off use does not fix a return problem.

Then offer the version of the feature that already exists in principle.

## 6. "What do we have that an alternative lacks?"
The full analysis belongs to `moat-analysis` in the product strategist profile, when it is installed. Without it, answer with an honest split in two columns:

- **Not an edge**: what a competitor can copy quickly (infrastructure, know-how that fits in a prompt or a configuration), and what the user can buy elsewhere, the same.
- **An edge**: what the alternative structurally does not do, such as reaching out first, remembering each case over weeks, sitting on the recurring moment, or learning what worked for this user.

Mark which rows of the edge column are reachable at today's volume. An edge nobody has reached yet is a hypothesis.
